+
+
+

+
+
+A stock clerk may need to find a product ID, whereas a report needs the IDs in ascending order. **Searching** finds a matching position; **sorting** rearranges values into an order. Both use the indexing, loops, and method contracts already introduced. A search result is an index, not the stored value. The value `-1` means no match because valid array indices begin at zero.
+
+| Task | Input requirement | Result | Changes the array? |
+| --- | --- | --- | --- |
+| Linear search | No ordering required. | First matching index, or -1. | No. |
+| Binary search | Ascending order required. | A matching index, or -1. | No. |
+| Insertion sort | No ordering required. | Same values in ascending order. | Yes, in the version here. |

+## Linear Search: Check Positions in Order
+
+
+
+```{index} cs1 arrays: linear-search
+```
+
+
+Start at index zero and compare each value with the target. Return immediately on a match. If the loop finishes, every position has been checked and the target is absent.[^ch07-linear]
+
+General definition/call pattern (schematic):
+
+```csharp
+static int LinearSearch(int[] values, int target) { /* scan and return an index */ }
+int position = LinearSearch(productIds, wantedId);
+```
+
+`int[] values` receives the array reference; `target` receives the value to find. Returning an index lets the caller distinguish absence from a stored zero and use the position to access the matching element safely.
+
+For `[19, 4, 25, 8, 12]` and target 8, read the trace from top to bottom:
+
+| Index i | Value | Equal to 8? | Action |
+| ---: | ---: | --- | --- |
+| 0 | 19 | No. | Advance. |
+| 1 | 4 | No. | Advance. |
+| 2 | 25 | No. | Advance. |
+| 3 | 8 | Yes. | Return 3; stop. |
+
+The example prints `3`, `-1`, and `0`: position three contains 8, 7 is absent, and the first of two matching 8s is at position zero. An empty array performs no comparisons and returns -1. A common mistake is placing `return -1` inside the loop: one nonmatching item does not establish absence. Another is reading `values[position]` before checking that `position >= 0`.
+
+
+using System;
+static int LinearSearch(int[] values, int target)
+{
+    for (int i = 0; i < values.Length; i++)
+        if (values[i] == target) return i;
+    return -1;
+}
+int[] ids = { 19, 4, 25, 8, 12 };
+Console.WriteLine(LinearSearch(ids, 8));
+Console.WriteLine(LinearSearch(ids, 7));
+Console.WriteLine(LinearSearch(new[] { 8, 8 }, 8));
+

+## Binary Search: Narrow a Sorted Interval
+
+
+
+```{index} cs1 arrays: binary-search
+```
+
+
+When IDs are already sorted, a middle comparison tells you which half can still contain the target. If the middle value is too small, discard it and everything to its left; if it is too large, discard it and everything to its right. This reasoning depends on ascending order.[^ch07-binary]
+
+General call pattern (schematic):
+
+```csharp
+int position = BinarySearch(sortedIds, wantedId);
+```
+
+The method uses the same parameter/return types as linear search, but has a different precondition: `sortedIds` must be ascending. It does not check or sort the array for you. Here `low` and `high` are inclusive candidate bounds. `low <= high` means that at least one candidate remains. Integer division chooses a middle index; `low + (high - low) / 2` also avoids adding two potentially large indices.
+
+Trace target 19 in `[4, 8, 12, 19, 25]`:
+
+| low | high | middle | Value | Next action |
+| ---: | ---: | ---: | ---: | --- |
+| 0 | 4 | 2 | 12 | Set low to 3. |
+| 3 | 4 | 3 | 19 | Return 3. |
+
+For absent target 20, the bounds eventually become low = 4 and high = 3. The interval is empty, so return -1. In an empty array, high begins at -1 and the loop never indexes the array. The example prints `3`, `-1`, and `-1`.
+
+Common mistakes are searching unsorted input, using `<` instead of `<=` and missing the final candidate, or updating a bound to `middle` without excluding the already tested value. The `+ 1` and `- 1` guarantee progress. With duplicates, this version can return any matching position; it does not promise the first match. Its index refers to the sorted array, which may have a different position order from the original input.
+
+
+using System;
+static int BinarySearch(int[] values, int target)
+{
+    int low = 0;
+    int high = values.Length - 1;
+    while (low <= high)
+    {
+        int middle = low + (high - low) / 2;
+        if (values[middle] == target) return middle;
+        if (values[middle] < target) low = middle + 1;
+        else high = middle - 1;
+    }
+    return -1;
+}
+int[] ids = { 4, 8, 12, 19, 25 };
+Console.WriteLine(BinarySearch(ids, 19));
+Console.WriteLine(BinarySearch(ids, 20));
+Console.WriteLine(BinarySearch(Array.Empty<int>(), 19));
+
+
+**Guided practice: repair the boundary.** The starter incorrectly uses `low < high`. Predict what happens for `[12]` with target 12 before running it. Repair the loop condition, then check first/last matches, absence below and above the range, and empty input. For duplicates, verify that a returned index holds the target rather than insisting on a particular index. Explain why these tests do not remove the sorted-input precondition.

+## Insertion Sort: Grow an Ordered Prefix
+
+
+
+```{index} cs1 arrays: insertion-sort
+```
+
+
+To prepare an ascending report, treat the first item as an already sorted group. Take the next item, save it, shift larger preceding items one position right, and place the saved item in the opening. Repeat until the sorted group covers the whole array.[^ch07-sort]
+
+General definition/call pattern (schematic):
+
+```csharp
+static void InsertionSort(int[] values) { /* rearrange the elements */ }
+InsertionSort(reportIds);
+```
+
+The method returns `void` because its result is the changed array, not a separate array. An alias sees the same changes. If arrival order matters, allocate a separate array and copy the integer elements first, then sort the copy. Copying the reference alone does not protect the original.
+
+| Pass | Saved value | After inserting it | Sorted prefix |
+| --- | ---: | --- | --- |
+| Start | None. | `[8, 4, 8, 2]` | `[8]` |
+| i = 1 | 4 | `[4, 8, 8, 2]` | `[4, 8]` |
+| i = 2 | 8 | `[4, 8, 8, 2]` | `[4, 8, 8]` |
+| i = 3 | 2 | `[2, 4, 8, 8]` | Whole array. |
+
+On the last pass, save 2 before shifting 8, 8, and 4 right. During the shifts the array temporarily contains repeated values; the saved local variable preserves the displaced item. `j` can become -1, so test `j >= 0` before reading `values[j]`. The opening is then `j + 1`, which can be zero.
+
+The complete example prints the sorted copy `2,4,8,8`, then the unchanged original `8,4,8,2`. Empty and singleton arrays need no insertion passes. Already sorted input still works. A common mistake is omitting `values[j + 1] = saved`, which loses a value; another is sorting an alias while expecting the original to remain unchanged. Shifting only values strictly greater than `saved` also leaves equal values in their original relative order, a property Chapter 16 examines with labeled records.
+
+
+using System;
+static void InsertionSort(int[] values)
+{
+    for (int i = 1; i < values.Length; i++)
+    {
+        int saved = values[i];
+        int j = i - 1;
+        while (j >= 0 && values[j] > saved)
+        {
+            values[j + 1] = values[j];
+            j--;
+        }
+        values[j + 1] = saved;
+    }
+}
+int[] original = { 8, 4, 8, 2 };
+int[] report = new int[original.Length];
+for (int i = 0; i < original.Length; i++) report[i] = original[i];
+InsertionSort(report);
+Console.WriteLine(string.Join(",", report));
+Console.WriteLine(string.Join(",", original));
+
+

Sorting must preserve values as well as establish order.

+**Connect the choices.** For one lookup in arrival-order data, a linear scan needs no preparation. Binary search narrows the candidates quickly only when suitable order already exists or has been prepared. Insertion sort changes order and does work of its own; sorting solely to answer one small lookup is not automatically a good trade. For repeated lookups, consider preparation and later updates as well. Chapter 16 develops those comparisons and stronger duplicate/result policies. This chapter's algorithms are instructional implementations; a library method has its own documented contract.

+
+A branch-by-day table adds a second coordinate to the one-dimensional accumulation pattern. First fix the row and traverse columns; then repeat for another row. To total one day across branches, fix the column and traverse rows. `GetLength(0)` counts rows; `GetLength(1)` counts columns. `Length` counts every element and is not a valid bound for either coordinate alone.
+
+| Branch | Monday (column 0) | Tuesday (column 1) | Row total |
+| --- | --- | --- | --- |
+| North (row 0) | 2 | 5 | 7 |
+| South (row 1) | 4 | 1 | 5 |
+| Column total | 6 | 6 | 12 |
+
+For North, the accumulator moves from zero to two to seven. For Monday it moves from zero to two to six. The values are the same table; the coordinate held constant determines the question. Initialize an accumulator for each result, not once for all rows.
+
+
+using System;
+int[,] orders = { { 2, 5 }, { 4, 1 } };
+int north = 0;
+for (int column = 0; column < orders.GetLength(1); column++) north += orders[0, column];
+int monday = 0;
+for (int row = 0; row < orders.GetLength(0); row++) monday += orders[row, 0];

+Console.WriteLine(monday);
